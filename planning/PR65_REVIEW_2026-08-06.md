## 🔍 Detailed Component Review

### 1. `AddFile.php` — Scholar File Upload Wizard (637 lines)

**Architecture:** Multi-step wizard with 3 states:
- `fileType = null` → select "Scholar" or "Admin"
- `fileType = 'scholar'` → scholar form + dynamic scanned categories
- `fileType = 'admin'` → admin category → admin record form

**Key Features:**
- **Dynamic scanned categories** — add/remove/rename/reorder categories (lines 90-345)
- **Client-side file staging** — `pendingUploads` array with temp storage + thumbnails (lines 119-237)
- **Drag-and-drop reordering** — `reorderFiles()` by ID array (line 330)
- **Two save paths:**
  - `saveScholar()` — processes `scannedCategories` directly (data URLs + temp files)
  - `saveScholarWithStagedFiles(manifest)` — accepts manifest from frontend for staged uploads
- **File handling** — temp → permanent (`documents/`), base64 data URL decode, MIME detection
- **FileType auto-creation** — `firstOrCreate(['name' => categoryName])` with year

**Test Coverage:** 4 tests covering full cycle, reordering, pending uploads, manifest save.

### 2. `Scholars/Edit.php` — Edit Scholar + Document Management (122 lines)

**Architecture:** Model-bound component receiving `$scholar` via route model binding.

**Features:**
- **Full profile edit** — all scholar fields + contact info + `for_disposal` flag
- **Date formatting** — `birthdate`/`clearance_date` → `Y-m-d` for inputs (lines 70-75)
- **Document list** — shows existing documents in view (tested via `assertSee`)
- **Staged file save** — `saveScholarWithStagedFiles(manifest)` mirrors AddFile pattern
- **Document deletion** — `deleteExistingDocument($id)` soft-deletes (tested)
- **Mock fallback** — renders with "Wakin Cean Maclang" when scholar ID not found (line 200)

**Validation:** Strict rules, `spas_no` unique except self, email unique except self.

**Test Coverage:** 4 tests covering render, save, staged file + delete, fallback.
